# 语音发送

让机器人开口说话。**回复会自动变成语音发出来**，不用打任何指令；想安静一会儿，发一句 `/语音开关` 就切回文字。

合成交给配套的 `tts-rvc-service`（和 [TTS-RVC 语音回复](https://github.com/kuqiwang/astrbot_plugin_tts_rvc) 插件用的是同一个服务），服务端做的是

```
文字 → edge-tts 干声 → RVC 换声 → wav
```

所以发出去的语音已经是**换过声**的，音色就是你在 TTS-RVC 模型库里导入的那个。插件本身不碰模型、不装 torch，只负责「把文字递过去」和「把 wav 发出去」。

## 功能

- **自动语音** — 机器人每次回复都会转成语音，不用打指令
- **`/语音开关`** — 语音和文字之间来回切，单聊和每个群各自独立
- **`/说 <文字>`** — 单独合成一句发出来
- **`/发语音 <路径或网址>`** — 直接发一个现成的音频文件
- **`/音色列表`** — 列出声音服务上可用的音色
- **`/设置音色 <id>`** — 给当前群/私聊单独设一个音色，设 `默认` 恢复
- **`/语音配置`** — 看服务状态、地址来源、当前音色、当前是发语音还是发文字
- **`/语音帮助`** — 命令速查

中英文命令都能用：`/语音开关` 等于 `/vswitch`，`/说` 等于 `/vsay`，`/发语音` 等于 `/vsend`，`/音色列表` 等于 `/vvoices`，`/设置音色` 等于 `/vset`，`/语音配置` 等于 `/vinfo`，`/语音帮助` 等于 `/vhelp`。

## 回复方式怎么定

先看会话，再看全局：

1. 这个会话里发过 `/语音开关 语音` 或 `语音`（`/语音开关 文字` 或 `文字`）——按这个来
2. 没设过会话级，就看配置里的 `auto_mode`（默认开，也就是默认发语音）
3. `/语音开关 默认` 可以清掉会话设定，回到跟全局走

不带参数发 `/语音开关` 就是直接切反：现在发语音就切成文字，现在发文字就切成语音。

## 和 TTS-RVC 的关系

两者都能把回复转成语音，功能是重叠的：

- TTS-RVC 是「每条回复都转」，用 `/打开语音`、`/关闭语音` 控制
- 这个插件是「每条回复都转，而且能用一句话切成文字」，控制更细，还多了 `/说`、`/音色列表` 这些手动入口

**建议只启用其中一个**，都开着的两套逻辑会互相抢。声音服务本身是共用的，切到哪个都还能用同一个音色。

服务地址按这个顺序找，先找到的算数：

1. 本插件配置里的 `tts_service_url`（想单独指定就填这里）
2. 读 `data/config/astrbot_plugin_tts_rvc_config.json` 里的 `service_url`
3. 都没有就用默认的 `http://127.0.0.1:9880`

默认音色同理：自己的 `default_voice_id` 为空时，用 TTS-RVC 配置里的 `voice_id`。

## 安装

1. 插件市场搜索「语音发送」安装，或者把这个目录放进 `data/plugins/`
2. 确保声音服务在跑（默认 `http://127.0.0.1:9880`）
3. 确认插件是**启用**状态（装了不等于启用，面板上那个开关要打开）

只依赖 `aiohttp`，AstrBot 自带，不用额外装。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `auto_mode` | `true` | 自动语音；关掉就只发文字（会话里还能用 `/语音开关` 单独改） |
| `auto_scope` | `all` | 自动语音范围：`all` / `private` / `group` |
| `auto_dual` | `false` | 文字和语音一起发 |
| `auto_min_chars` | `2` | 少于这么多字不转语音 |
| `auto_max_chars` | `150` | 超过这么多字保持文字 |
| `auto_admin_only` | `false` | 只给管理员自动语音 |
| `defer_to_tts_rvc` | `false` | 让位给 TTS-RVC（两个都开时才需要打开） |
| `tts_service_url` | `""` | 声音服务地址，留空自动沿用 TTS-RVC |
| `default_voice_id` | `""` | 默认音色，留空沿用 TTS-RVC |
| `admin_only` | `true` | 只有管理员能用命令 |
| `allowed_users` | `[]` | 额外放行的 QQ 号 |
| `allowed_groups` | `[]` | 额外放行的群号 |
| `allow_dirs` | `["/shared"]` | 允许发出去的本地音频目录 |
| `allow_url` | `false` | 允不允许直接发外链音频 |
| `max_text_chars` | `300` | 一次最多合成多少字 |
| `max_file_mb` | `20.0` | 音频大小上限 |
| `timeout` | `90.0` | 合成超时秒数 |
| `cache` | `true` | 同一句话同一音色缓存，不重复合成 |
| `rate_limit_per_min` | `6` | 每人每分钟最多几次命令 |

## 支持平台

- **aiocqhttp**（NapCat / Lagrange / SnowLuma / go-cqhttp）——语音用 `Record` 消息段，普通语音条
- **qq_official**（QQ 官方机器人）——走内核文件消息段，按被动回复发送

## 安全

- 本地音频只发 `allow_dirs` 里的（插件自己的数据目录永远可读），`..` 和软链接逃逸会被拦
- 默认只给管理员用命令，可以按 QQ 号 / 群号白名单放开
- 有频率限制，默认每人每分钟 6 次
- 合成失败只会退回文字，不会吞消息；连续失败熔断几十秒，避免拖慢聊天

## 排错

**一直说「连不上声音服务」**

先在服务器上 `curl http://127.0.0.1:9880/health`。如果 AstrBot 跑在 Docker 里，容器内的 `127.0.0.1` 是容器自己；声音服务在宿主机上就写 `http://<宿主机IP>:9880`，或者把两个服务放进同一个 compose 网络，用服务名访问。

**命令发了没反应，或者机器人拿它当普通聊天回复**

先确认插件是不是启用状态（面板上的开关），再确认消息前缀。AstrBot 的命令要带唤醒前缀，默认是 `/`。

**合成失败但服务是好的**

看日志里服务返回的内容。文本太长、音色 ID 不存在、模型还没加载完，都会返回错误。插件会把服务端的报错翻译成人话，常见两种：

提示「还缺 RVC 推理模型（HuBERT / RMVPE）」——服务端少了推理模型，在语音服务目录里跑：

```bash
runtime\.venv\Scripts\rvc-next.exe --data-dir runtime\rvc-data assets download hubert rmvpe --source hf-mirror
```

下完重启语音服务。

提示「缺 edge-tts 这个依赖」——干声生成器没装：

```bash
runtime\.venv\Scripts\python.exe -m pip install edge-tts
```

**`/发语音` 提示路径不在允许目录**

把音频所在目录加进 `allow_dirs`。不想配的话，把文件放进插件的数据目录。

**`/说` 说没权限**

默认只给管理员用。配置里 `admin_only` 改成 `false`，或者把自己的号加进 `allowed_users`。

## 目录

```
astrbot_plugin_voice_sender/
├── main.py              插件主体：命令、自动语音钩子、联动探测
├── voicekit/
│   ├── tts.py           声音服务客户端：/health、/voices、/tts，报错翻译
│   ├── audio.py         音频识别、时长、大小校验
│   └── state.py         会话音色与回复方式、限流

├── metadata.yaml        插件元信息
├── REQUIREMENTS.txt     aiohttp
└── selfcheck.py / smoke_test.py  离线自检
```

## 测试

不装 AstrBot 也能跑：

```bash
python selfcheck.py   # 离线单元自检
python smoke_test.py  # 造一个 AstrBot 桩，真实 import 并跑命令与钩子
```

## 说明

声音服务跑在哪儿，语音就在哪儿合成。服务跑在本地 Windows 上的话，那台机器关机或者睡眠，语音就发不出来（文字照常）。想彻底脱离，把 RVC 服务搬到有显卡的服务器上就行。
